# 설명 강도·적용 조건 전달 경로 점검

검토일: 2026-11-10. 코드와 생성 결과를 변경하지 않은 읽기 중심 점검이다.

## 결론

현재 자료에서 확인되는 주된 손실 지점은 **analysis → discover의 정책 통합**이다. analysis에는 설명 시점·분량·하위 유형·비관찰 기록이 있지만, 정책은 이를 행동 이름과 넓은 Trigger로 압축한다. generate는 이 정책을 받아 적용하며, 관찰 한계·낮은 확신·설명량을 실행에 반영하는 구체적 규칙이 없다.

따라서 'analysis가 처음부터 설명 강도를 전혀 기록하지 않았다'는 진단은 맞지 않는다. 다만 국소적 비관찰 장면이 채워지지 않았고, 복잡도에 따라 강도를 선택하는 기준은 현재 자료만으로 확정하기 어렵다. 실제 원인별 영향의 크기는 프롬프트를 분리해 실험해야 알 수 있다.

## 검토 범위와 확인 방법

- data/teacher_profile/analysis/v4/의 JSON 12건, 대응 분석 보고서 12건, 근거 전사, data/teacher_profile/profiles/teacher_policy_v4.md, generate.py의 정책 프롬프트를 확인했다.
- 기존 V1과 현재 policyV4 결과 7건을 대조했다. 학습 분석 005와 생성 테스트 test005는 서로 다른 문제다.
- JSON 12건은 현재 validate를 통과했고, 현재 render로 재구성한 텍스트는 저장된 분석 보고서와 모두 일치했다. JSON에서 보고서로 옮기는 코드가 시점·분량을 버린 문제는 아니다. 내용 판정의 정답을 검증했다는 의미는 아니다.
- 보관된 두 실행 폴더의 정책 사본은 현재 data/teacher_profile/profiles/teacher_policy_v4.md와 바이트 단위로 동일했다. 다만 최초 6개 생성의 실행 메타데이터는 없어 코드·출력의 대응만 확인할 수 있다.
- 새 모델 호출, 정책 재추출, 생성 재실행은 하지 않았다.

## 1. 회고: 일부 문제의 관찰이 모든 풀이 종료 시점의 지시로 확대됨

### 전사·analysis

T05는 013·014·015의 3문제에서 관찰됐다. 나머지 9문제의 unobserved_checks에는 회고가 관찰되지 않았다고 기록돼 있다.

003은 전사 L15–16에서 목표 f(2)를 계산한 뒤 종료한다. teacher_profile/analysis/v4/003.txt:120도 T05 비관찰을 기록한다. 016도 전사 L21–23에서 답을 계산한 뒤 종료하며 teacher_profile/analysis/v4/016.txt:155에 회고 비관찰이 있다.

반대로 015의 L57–61은 역함수 존재 → 도함수 부호 → 접함 조건을 되짚고, '계산은 많았으나 어려운 내용은 이거 하나였다'고 핵심과 나머지를 구분한다. 단순한 풀이 전체의 재요약과는 기능이 다르다. JSON에서 T05 세 장면은 모두 '풀이 종료 후 / 상세 전개'다.

### 정책에서 바뀐 것

teacher_profile/profiles/teacher_policy_v4.md:462의 G-T5 Trigger는 '문제 풀이가 완료되고 정답이 도출된 직후 시점'이다. 관찰 한계(:493)에 긴 고난도 풀이 3건이라고 쓰였지만, Trigger에는 그 맥락이 없고 시점·강도별 실행 기준도 없다.

빈도는 3/3으로 표기된다. 그런데 위 Trigger를 문자 그대로 적용하면, 답을 내고 끝난 003·016 등도 검토 대상이다. 따라서 3/3은 현재의 넓은 Trigger와 분모의 일관성이 없다. 이는 회고 확률이 25%라는 뜻도 아니다. '12건 중 3건에서 회고가 관찰됐다'와 '동일 Trigger에서의 선택 비율'은 구분해야 한다. 비관찰은 촬영·전사 범위 밖에서도 하지 않았다는 증거가 아니다.

### 생성 결과

policyV4 7건 모두 회고·복습·핵심 요약 절이 있다. test001:78부터도 두 항목의 회고가 붙는다. test004는 V1과 V4의 풀이 본문이 같고 회고 절만 추가됐다.

### 판정

비관찰 기록이 analysis에 없었던 것이 아니다. discover가 지지 사례 밖의 관찰 범위를 적용 경계로 충분히 반영하지 못했고, generate가 관찰 한계를 선택 조건으로 다루지 못했다. '어려운 문제에서만 회고한다'는 새 규칙은 아직 확정할 수 없다.

## 2. 목표 제시: 짧은 계산 연결이 매 단계의 목표 선언으로 바뀜

### 전사·analysis

003 L15의 '그럼 이제 f2를 다시 구해 보면'은 최종 계산 직전의 짧은 언급이다. JSON의 T01도 '관련 행동 전 / 짧은 언급 / 최종 목표 재확인'이다.

전체 T01 관찰 12장면 중 9장면은 짧은 언급, 3장면은 연결 설명이다. 시점도 실행 중 8, 관련 행동 전 3, 풀이 종료 후 1로 구분돼 있다. 009·012는 목표 제시 비관찰이 기록돼 있다.

### 정책에서 바뀐 것

G-T3(:316)의 Trigger는 '풀이를 시작하는 시점 또는 특정 단계의 주요 연산/추론으로 진입하는 시점'이다. 그러나 같은 정책의 대표 인용에는 최종 계산 직전 발화가 포함된다. 원래의 최종 목표 재확인과 중간 목표 설정, 짧은 언급과 연결 설명이 하나의 실행 규칙으로 합쳐졌다.

### 생성 결과

test005:7–9는 최종 목표를 연속으로 언급하고 하위 목표를 선언한다. test001:29는 구한 f(1)을 '중간 하위 목표'라 부른다. 목표를 짚는 기능은 존재하지만, 원문에서 관찰된 자연스러운 짧은 연결보다 용어와 구조가 확대됐다.

### 판정

강도와 하위 유형은 analysis에 있다. discover의 출력 형식에는 이를 보존해야 할 필드가 없고 generate에도 '짧은 목표 연결'을 재현하는 규칙이 없다. 정책의 Final Goal/Sub-goal 용어가 학생 출력에 나타난 점도 확인되지만, 이것만으로 생성 원인을 단정하지는 않는다.

## 3. 차함수: 전략 전환의 조건이 '부등식 존재'로 넓어짐

### 전사·analysis

014 L36–48에서 강사는 현재 부등식에서 그래프적 의미를 찾으려는 접근의 한계를 설명하고, F-f ≥ 0으로 식을 다루겠다고 전환한다. analysis의 S06 Trigger와 T02/T04는 이 맥락과 전략 전환을 보존한다.

012 S04는 이미 정의한 h(x)에 맞춰 적분 아래끝을 0으로 바꾸고 h(m+2)>h(m)으로 해석한다. 이 사례는 014의 '기하적 의미 추론을 포기함'과 동일한 전환 조건이 아니다.

### 정책에서 바뀐 것

U-C2(:947)의 Trigger는 함수 대소 비교 또는 정적분 부등식이 제시된 상황이다. Action에는 '기하적/직관적 의미 추론을 포기'가 들어 있고, Applicable when에는 014의 접근 한계가 남아 있다. 즉, 같은 정책 안에서도 Trigger와 구체적 적용 조건의 폭이 다르다. 012·014의 다른 맥락도 병합됐다.

이 후보는 두 문제 근거, Confidence Low다. generate는 확정 정책과 Uncertain Candidates가 포함된 문서 전체를 받지만, 후보의 실행 권한을 구분하는 지시가 없다.

### 생성 결과

test005:16은 '항상 성립하는 부등식을 만난다면 … 차함수 … 로 접근해야 합니다'라고 말한다. 두 차함수 도입(:18, :63)과 마지막 회고(:110–111)에서도 그 방법을 권한다. 원래 전환 조건인 '현재 접근의 한계'는 제시되지 않는다.

### 판정 및 한계

조건 확대는 discover의 U-C2 Trigger에서 이미 확인되고, generate는 이를 필수적인 일반 루틴처럼 표현했다. 다만 V1도 차함수 두 개를 도입했으므로 v4 때문에 이 전략이 새로 생겼다고 볼 수는 없다. 수학적으로 타당한 방법을 택한 것과 이를 강사의 필수 전략으로 가르친 것은 별개다.

## 4. 선택 이유: 내용은 남았지만 '어느 선택에서 어느 정도 말하는가'가 사라짐

analysis의 T02는 총 17장면이다. 분량은 연결 설명 14, 짧은 언급 2, 상세 전개 1이다. 실행 전 4, 실행 중 13으로 기록됐다.

예를 들어 007 L5는 '아래 끝이 0이니까 0 대입해야죠' 한 줄이며 짧은 언급으로 기록됐다. 014의 전략 전환은 긴 근거와 함께 상세 전개로 기록됐다. 둘은 같은 '선택 이유 설명'이어도 강도가 다르다.

G-T1(:162)은 대입·미분·인수분해·변형 등 행동을 선택하는 시점 전반을 Trigger로 둔다. 반면 시점·분량의 차이와 구체적인 선택 유형별 경계는 정책에 없다. 12/12도 '각 문제에 한 번 이상 있었다'는 집계이지, 모든 선택에 설명을 붙였다는 뜻이 아니다(discover.py:209–215).

test001:19는 대입 이유를 설명하지만 test005:25는 'h=0을 대입하면 어떻게 되나요?' 뒤 결과를 제시한다. 전체 전략의 이유를 길게 말하는 것과 특정 대입값을 떠올리는 단서를 알려주는 것은 동일하지 않다. G-T1의 존재만으로 후자를 보장하지 못했다.

## 5. analysis에도 남은 구조적 한계

- 74개 Step의 observations 105건은 모두 status='관찰됨'이다. 항목 전체의 비관찰은 unobserved_checks에 있지만, 한 번 관찰된 항목의 다른 의사결정 장면에 대한 국소적 비관찰 기록은 없다.
- analyze.py:119–124는 그런 장면을 '남길 수 있다'고 하지만 필수 검토를 요구하지 않는다. 따라서 선택 이유를 한 번 설명한 강사가 다른 어떤 선택에서는 설명하지 않았는지 비교할 자료가 약하다.
- 관찰 17건/74 Step을 선택 이유 설명의 적용률로 계산하면 안 된다. 모든 Step이 같은 종류의 선택 기회가 아니고, Step 분할도 균일하지 않다.
- 현재 schema에는 설명 분량이 있지만, 그 장면의 추론 부담·기존 정보로 바로 처리 가능한지·새 표현 도입의 필요성을 대조하는 전용 기록은 없다. 이것은 '문항 난이도가 설명 강도를 결정한다'는 증거가 아니다.
- 일부 분류에는 재검토 여지도 있다. 예를 들어 014 S04의 T03은 '선택 이유 설명'이라고 기록했지만, 제시 인용은 주로 대안 언급과 선택·검산이다. 대안 간 선택 이유가 실제로 명시됐는지는 추가 검토가 필요하다. 전체 analysis의 정확성을 확정한 점검은 아니다.

## 6. 수정 순서 제안

1. discover부터 수정: 시점·분량·하위 유형, 관찰 범위, 비관찰 장면을 보존한다. 넓은 Trigger와 좁은 근거의 불일치를 점검한다. 문제 단위 출현 빈도를 장면별 실행 지시로 바꾸지 않는다. 전환 조건이 다른 사례를 병합하지 않는다.
2. generate 수정: 정책을 가능한 행동들의 조건부 선택으로 사용한다. 낮은 확신의 후보를 필수 루틴으로 말하지 않는다. 목표·회고를 매 단계 고정 형식으로 강요하지 않는다. 관찰된 설명 강도를 참고하고 근거가 없는 '항상/반드시'를 제한한다. 증명에 필요한 설명은 유지한다.
3. 위 변경만 적용해 기존 analysis로 정책을 별도 버전으로 추출하고, 대표 테스트를 별도 버전으로 생성해 비교한다. 두 단계의 효과를 분리하려면 정책 고정/생성 프롬프트 변경 등 조건을 나누어 실험한다. 자동 개선을 보장하지 않는다.
4. 남은 실패에 한해 analysis의 국소적 관찰 기회를 보강한다. 행동이 안 보인다는 사실과 강사가 의도적으로 생략했다는 해석을 분리한다. 새로운 분석은 기존 파일을 보존한 별도 버전에 저장한다.

지금은 기존 analysis를 전량 다시 만들거나 사람이 결과를 수동 교정하는 것이 첫 단계일 필요가 없다. 이미 있는 강도·시점·비관찰 정보부터 downstream으로 보존하는 수정이 우선이다.
